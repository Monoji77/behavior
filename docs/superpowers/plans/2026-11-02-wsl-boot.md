# Unattended WSL Startup Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan. Steps use checkbox syntax for tracking.

**Goal:** Recover Behavior services before Windows sign-in.
**Architecture:** A password-logon Task Scheduler boot task owns the existing
WSL keepalive launcher. An elevated installer validates same-user WSL access
through a temporary scheduled task before replacing the login shortcut.
**Tech Stack:** Windows PowerShell 5.1, ScheduledTasks, WSL, Pester.
**Spec:** `docs/superpowers/specs/2026-11-02-wsl-boot-design.md`

## Global Constraints

- One PR; no merge, approval, or application promotion.
- Never put credentials in files or process arguments.
- No Kubernetes manifests, images, database content, or Tailscale route changes.
- Do not reboot the laptop during this work.

## Review Focus

- A wrong Windows account must not create a task against a different WSL installation.
- A failed batch-logon WSL probe must leave the login fallback intact.
- Battery transitions and the default three-day task limit must not stop the launcher.
- Checkout paths and spaces must survive installation into LocalAppData.
- An unrelated scheduled task or Startup shortcut must not be overwritten or deleted.

### Task 1: Boot task installer and verification

**Files:**
- Create: `infrastructure/wsl/New-BehaviorWslBootTask.ps1` (task definition)
- Create: `infrastructure/wsl/Install-BehaviorWslBootTask.ps1` (host installer)
- Create: `infrastructure/wsl/BootTask.Tests.ps1` (Windows policy tests)
- Modify: `infrastructure/wsl/README.md` (activation, verification, rollback)

**Interfaces:**
- Consumes: `Start-BehaviorWsl.ps1`, holding `wsl.exe ... sleep infinity` open.
- Produces: `New-BehaviorWslBootTask -UserId <sid> -LauncherPath <absolute path>`
  returning a ScheduledTasks CIM task definition without registering it.
- Installer supports `-WhatIf` without credentials, elevation, or mutations.
